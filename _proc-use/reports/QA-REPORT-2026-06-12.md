### P2(下个版本 v2.1+ 修)
1. **无覆盖率工具** — 没有 c8/nyc 输出 %,无法判断行/分支覆盖。建议下版本集成。
2. **`node scripts/phase-state.js`(无参数)stderr 输出 `未知命令: undefined`** — 应改为 `未知命令: <空>` 或 `未指定命令`。
3. **`check-disk` 的 `df` 输出在 macOS / Linux 略有差异** — 当前用 `-P` 标准化(1024-byte blocks),但解析逻辑 `parseInt(parts[3] || parts[2])` 是 fallback,主路径假设 Available 在第 4 列。极端 BSD df 输出(无 -P)走 fallback 路径,文档化但未测试。
4. **`writeState` 备份轮转** — 每次都 `copyFileSync` 两个文件,3 次写盘(主 + bak.1 + bak.2)。可优化:只在 state 大小变化或非空状态时备份。当前实现可工作但非最优。
5. **无 Windows 测试** — 所有 `set -euo pipefail` / `date -j -f` / `ps -o` 都是 BSD/GNU 风格,Windows(MSYS/Git Bash)兼容性未验证。
6. **P1-3 修复后 `watchdog.sh` 第 76 行**:`node -e "..."` 嵌入 require 解析 state.json,无 try/catch 包裹外层(虽 `|| echo "NO"` 兜底,但 stdout 仍可能混入 stderr 噪音)。

### P3(技术债,长期)
1. **SKILL.md 1513 行超大** — 单文件超工程实践静态语言 400 行上限。markdown 文档豁免,但跨章节导航(目录/TOC)缺失,新读者上手成本高。建议 v3.0 拆分为 `SKILL-core.md` / `SKILL-bugs/`。
2. **`references/templates/` 下审计/集成测试报告模板** 与 SKILL.md 协议中描述的内容脱节(模板内容未跟进 Bug-05 methodology 等改动)。
3. **`ALERT.md` 触发条件(3-strike)在 watchdog / phase-state.js 中无显式触发逻辑** — SKILL.md 协议定义但代码层只返回 `maxed: true`,orchestrator 负责实际写文件。协议-代码分工合理但容易遗漏。
4. **`_proc-use/docs/DESIGN.md`(13K)与 `_proc-use/docs/README.md`(5.5K)未被 README 引用** — 设计文档存在但与新用户主入口脱节。
5. **`networkStatus` / `exitReason` 死字段删除** — 如果用户老 state.json 仍有这俩字段,`get` 命令仍会读出,但无写回逻辑。已删除字段应明确"读取时忽略"或加迁移。
